# AGENTS.md

This file provides guidance to coding agents working in the CTS. See the parent
`AGENTS.md` for overall SDK context, and `CONTEXT.md` here for the vocabulary
(Test / Axis / Permutation / Variant / Case / Channel / Ground truth / Workdir).

## Overview

The CTS (Conformance Test Suite) validates ANARI device implementations. It is a
self-contained C++ command-line tool, `anariCts`, that renders each test, checks
its Cases against each other on the device's own output (effect for a
Permutation axis, equivalence for a Variant axis, ADR-0010), scores them against
ground truth generated by a reference device (helide) where the Test has it,
*and* reports on the results tree (`report`, ADR-0008). A thin Python
layer (`ctsReport.py`) is retained only for the one output not worth porting to
C++ — the `reportlab` PDF. Everything communicates through files only — there is
no pybind11, no JSON scene format, and no Python orchestration (these were
removed; see `docs/adr/0001`–`0002`).

## Build Commands

```bash
# From the SDK root build directory. The tool builds under BUILD_CTS or BUILD_TESTING.
cmake -DBUILD_CTS=ON -DBUILD_HELIDE_DEVICE=ON ..
cmake --build . -j
```

Relevant targets: `anariCts` (the CTS tool), `anari_cts_core` (the internal
static library holding the catalog + runner), `anari_test_scenes` (shared scene
and generator utilities), and `anariCatalogTests` (the unit tests).

### Running locally

A stale install of the anari libs on `LD_LIBRARY_PATH` can shadow a fresh build
("undefined symbol" at runtime). Prepend the build dir when running:

```bash
cd build
LD_LIBRARY_PATH="$PWD:$LD_LIBRARY_PATH" ./anariCts run helide --workdir /tmp/run
LD_LIBRARY_PATH="$PWD:$LD_LIBRARY_PATH" ./anariCatalogTests
```

## Running the suite

```bash
anariCts generate --workdir myrun      # ground truth from the reference device (helide)
anariCts run helide --workdir myrun    # render + score a candidate against it
anariCts run rtx --workdir myrun -p ambientSample=4   # custom renderer params
anariCts report myrun [--all] [--html out.html] [--embed]  # text + optional HTML
python ../cts/ctsReport.py report myrun --pdf out.pdf      # PDF only

anariCts list [--filter <pat>]         # enumerate the catalog
anariCts query-features <device>       # device extensions
anariCts query-metadata [--filter <pat>]   # catalog metadata as JSON (no device)
anariCts query-device-info <device>    # device introspection: object subtypes + parameter metadata
anariCts check-properties <device>     # per test: runnable vs skipped + missing features
anariCts check-discrimination --workdir myrun [--all]  # Ground truth that can't tell its Cases apart
```

`check-discrimination` reads the Ground truth `generate` wrote (no device) and,
for every pair of Cases differing in one Permutation value (not Variant,
`frame_<channel>_type` or `.noEffectCheck` axes), scores one's Ground truth
against the other's with the Test's own thresholds. A pair that passes is
indistinguishable: the Ground-truth comparison can't tell those two values
apart. It exits 1 on any such pair not on the allow-list,
`tests/IndistinguishableGroundTruth.cpp` (each entry with its reason; `--all`
lists the allowed ones too), and 2 when there is no Ground truth to compare.
The ctest `cts_tool::discrimination::check` (with `BUILD_HELIDE_DEVICE`) runs
it on the default Reference device's Ground truth.

`query-device-info` is genuine device introspection (the old `anariInfo`
capability): `--type`/`--subtype` restrict by name substring, `--skip-parameters`
lists subtypes only, `--info` adds per-parameter default/min/max/use/values/
element types/description/source extension. It is distinct from
`query-metadata`, which dumps the catalog's shape.

`--filter` is a substring or glob (`*`,`?`) matched case-insensitively over a
test's `<category>/<test>` id; a pattern with two `/` is also matched over a
Case's `<category>/<test>/<case>` id, to select some Cases of a Test; the partners their self-checks need are then
rendered as support renders (images only, not counted). `run` and `report`
exit non-zero on any failure.

`run` without ground truth still evaluates the self-checks: a Case that passes
them is "passed, Ground truth not evaluated" (counted on its own line), and
only a Case with nothing to evaluate is skipped. `generate` writes a Variant's
shared ground-truth file from its first value's Case, skips `.noGroundTruth()`
Tests, and warns when the reference device's own Variants disagree.

Before the first Case, `run` and `generate` render a small probe frame (an
empty world). A device that can't render it (say, helide_gpu without SDL3 on
the loader path) stops the command with exit code 2 and one error naming the
device's own ERROR messages, instead of failing every Case. `run` then writes
`results/run.json` (not a Sidecar: it has no `verdict`), and `report` leads
with "device could not render: <reason>" and exits non-zero. A run whose device
renders the probe removes that record.

## Architecture

```
anariCts                 CLI dispatch: cts/src/main.cpp
  anari_cts_core          internal static CTS implementation
    DeviceIntrospection   frontend utility for query-device-info
    anari_test_scenes     shared scene and generator utilities
  Catalog                 in-C++ registry of every Test (one per-category file)
  Runner                  per Case: build world -> render each Channel -> generate GT or score vs GT;
                          per Test: relational pass (Relations) -> sidecars
  Relations               pure effect/equivalence pass over a Test's Cases (ADR-0010)
  Metrics                 SSIM / PSNR / changed fraction (single source of metrics, ADR-0004)
  Workdir / Sidecar       results/ ground_truth/ assets/ tree; per-Case sidecar JSON (ADR-0003)
  Report / HtmlReport     read the results tree -> text / HTML summary (ADR-0008)
ctsReport.py              reads the results tree too; retained only for the PDF
```

### Key source files (`src/anari_test_scenes/cts/`)

**Harness / runner:**
- `TestDef.h` — a registered Test: human-readable `description`, `build`
  (world), optional `cameraBuild` / `rendererConfig` hooks (ADR-0006) and
  `behaviorCheck` hook (with an optional `timeout` and `failOnDeviceErrors`,
  ADR-0009), axes, required features, thresholds (test-wide + per-channel),
  channels.
- `TestBuilder.{h,cpp}` — the `makeTest(...)` fluent builder. Note the verb is
  `requireFeatures()`, not the C++20 keyword `requires`. `covers(ext)` names a
  primary extension (the Test is evidence for it; also required);
  `requireFeatures()` alone declares support extensions. The shared support
  sets are in `cts/tests/Categories.h`.
- `Axis.h` / `Case.{h,cpp}` / `Expansion.{h,cpp}` — axes expand into Cases
  (cartesian, or one-factor-at-a-time when `simplified`); variants share a
  ground-truth key, permutations get distinct ones.
- `Catalog.{h,cpp}` / `Filter.{h,cpp}` — the registry and its substring/glob filter.
- `BuildContext.{h,cpp}` / `Value.{h,cpp}` — per-Case axis values handed to
  `build()`, backed by `helium::ParameterizedObject`.
- `Runner.{h,cpp}` — builds, renders, and scores Cases; owns renderer creation
  and baseline configuration, owns the default camera, and runs the behavior
  hook for behavioral tests: a timed one's Cases through its `CaseIsolation`,
  when it has one, and fails them on device errors if the Test asks.
- `Isolation.{h,cpp}` — `runProcess()` (start a process, kill it at a
  timeout; POSIX and Windows), `currentExecutable()`, and `CaseIsolation` /
  `ProcessCaseIsolation`: `anariCts run` re-running itself with
  `--isolated-case` for each Case of a timed Test (ADR-0009).
- `DeviceErrorLog.{h,cpp}` — the ERROR messages a device reported, recorded
  by the status callback, for `failOnDeviceErrors` and the probe frame.
- `DeviceProbe.{h,cpp}` — `probeDevice()`, the probe frame the Runner
  renders before the first Case.
- `DeviceFailure.{h,cpp}` — the run record (`results/run.json`) of a device
  that could not render the probe frame; files only, so `report` reads it.
- `FrameReadback.{h,cpp}` — validates mapped frame descriptors and converts
  supported per-Channel formats behind the shared map/unmap boundary.
- `FrameFormats.{h,cpp}` — resolves a Case's per-Channel output `ANARIDataType`
  from its `frame_<channel>_type` axis (color/albedo/normal); pure + unit-tested.
- `RendererParams.{h,cpp}` — pure parsing of CLI `--renderer-param NAME=VALUE`
  overrides into ANARI-typed bytes (unit-tested). The runner resolves each
  name's type from device introspection (falling back to inference) and sets it
  on every Case's renderer before the Test's own `rendererConfig`, so it stays
  device-agnostic and a renderer Test still wins on conflict.
- `Metrics.{h,cpp}` / `Image.{h,cpp}` — SSIM/PSNR, `changedFraction` (and its
  mask) for the self-checks, and PNG I/O (stb).
- `Discrimination.{h,cpp}` — `check-discrimination`: the pairs of Cases that
  differ in one Permutation value (`discriminationPairs`, pure), scoring their
  Ground truth against each other with the Test's thresholds, and matching the
  indistinguishable ones against the allow-list. The allow-list itself is
  `tests/IndistinguishableGroundTruth.cpp`.
- `Relations.{h,cpp}` — the pure relational pass (ADR-0010): groups of Cases
  differing in one axis, effect (all pairs, attributed to the later Case) and
  equivalence (with the first value's Case), the default tolerances
  (`SelfCheckDefaults`), which partners a filtered run must render
  (`renderSet`), the verdict as a conjunction (`settleVerdict`), and reading a
  Case's images back from the results tree (`loadCaseRender`). No device.
- `Workdir.{h,cpp}` / `Sidecar.{h,cpp}` — the results tree layout and the
  versioned per-Case sidecar contract (carries the producing `device` identity
  since schema v2 plus optional Test descriptions; `Workdir` also keys the
  per-channel diff/threshold images). `Sidecar` both writes (`toJson`/
  `writeSidecar`) and reads (`fromJson`/`readSidecar`) the contract.
- `Report.{h,cpp}` — reads the results tree (`loadResults`), aggregates it
  (`summarize`, `runDevice`, and per extension `extensionCoverage` over the
  canonical KHR list from `code_gen/api/` and the covered extensions the run
  recorded of its Catalog, `runCoveredExtensions`, plus a `core` row), and
  emits the text summary. `kReportMetrics` is
  the single list of reported metrics. Pure; unit-tested.
- `HtmlReport.{h,cpp}` — renders the self-contained interactive HTML report
  (inline CSS/JS, optional base64 `--embed`); pure `htmlEscape`/`base64Encode`
  are unit-tested.
- `GeometryLayout.{h,cpp}` — pure deterministic Layout generation using typed
  shape and primitive-mode enums.
- `GeometryBuilder.{h,cpp}` — geometry-family specifications and ANARI
  publication; one entry point per supported family.
- `ParameterBinding.{h,cpp}` — checked constant/attribute/sampler/unset
  material bindings. `SurfaceBuilder`, `LightBuilder`, `SamplerBuilder`,
  `VolumeBuilder`, `InstanceBuilder`, `ViewBuilder`, and `WorldBuilder` own the
  remaining focused construction responsibilities.

`query-device-info` is a thin CLI adapter over the shared frontend utility in
`src/anari/DeviceIntrospection.cpp`; the same utility backs `anariInfo`.

**Tests (the catalog):** `cts/tests/<category>.cpp` (geometry, material, sampler,
light, camera, frame, renderer, instance, volume, synchronization) each define a
`register<Category>Tests(Catalog&)`. `BuiltinTests.cpp` wires them all into the
catalog.

**Unit tests:** `tests/unit/test_cts_*.cpp` (catalog/expansion/filter/builder,
metrics, relations, discrimination, results/sidecar/workdir, report/html, runner, isolation).
Pure tests are tagged `[cts]`; device-backed ones add `[helide]` and self-skip if
no device loads. Images for pure tests are generated in code
(`tests/unit/cts_test_images.h`: solid, gradient, rectangle, disc); never add
an image file.

**Python:** `ctsReport.py` — the `report --pdf` path only; it reads the results
tree exactly as the C++ `report` does. Text and HTML live in C++.

## Extending the CTS

**New Test:** add a `makeTest(...)....registerInto(catalog)` to the relevant
`cts/tests/<category>.cpp`. Author the world in `build()` with ANARI C++ calls
plus the focused `*Builder.h` helpers; add a short `description()` of the
primary check, then declare axes, the primary extension(s) with `covers()`,
the support extensions the scene can't do without with `requireFeatures()`
(a missing one must skip the Test, not fail it; the shared sets in
`cts/tests/Categories.h` include the default perspective camera, so a Test
that brings its own camera requires that one instead), and channels.

Every Permutation axis is an effect check and every Variant axis an
equivalence check (ADR-0010). Pick values whose effect shows in a good share of
the frame (the default minimum is 1 % of pixels changed by more than 8 levels);
rework the scene rather than loosen it (`.effectMargin`) when a change is too
subtle, and opt an axis out (`.noEffectCheck(axis, reason)`) only when its
effect can't be judged by image difference. Declare `.groundTruth(reason)` when
appearance has no analytic answer, or `.noGroundTruth()` when the self-checks
say everything. A Test with Ground truth must also pass `check-discrimination`:
its Permutation values' Ground truth must fail as each other's. Don't add a
new Test to the allow-list; its seeded entries only shrink.

**New synchronization rule** (or any check a device fails by hanging): a
behaviour Test in `cts/tests/synchronization.cpp` with `.timeout(...)` and
`.failOnDeviceErrors()`. Make only calls the spec allows, force the state the
rule is about deterministically (e.g. map a shared array to hold a render
off) rather than by timing, and pick the next rule from ADR-0009's list.

**New per-Case axis the runner must act on** (e.g. a new output format): resolve
it in `FrameFormats.cpp` (pure, unit-test it) and honor it in `Runner.cpp`.

**New metric:** add it to `Metrics.{h,cpp}`, record it in the runner's
`ChannelResult`, add it to `kReportMetrics` in `Report.h` (the C++ text/HTML),
and to the `METRICS` list in `ctsReport.py` (the PDF). There is exactly one
metric *implementation*, in C++; the two reported-metric lists are just display
order for two independent readers of the one contract.

**Sidecar schema change:** the sidecar is a versioned cross-language contract
(ADR-0003) with two readers — the C++ `Sidecar` reader (`fromJson`) behind
`report`, and `ctsReport.py` for the PDF. A purely incidental optional field
(read with a default on both sides) need not bump `kSidecarSchemaVersion`. Bump
it when a change is either breaking *or* semantically significant to consumers —
i.e. a field they should know to rely on — and update both readers in lockstep.
v2 did the latter: it added the `device` object that labels a run (plus the
optional per-channel `diffImage`/`thresholdImage` debug paths). v3 added the
extensions behind a Case (`requiredFeatures`, `coveredFeatures`,
`missingFeatures`, `device.extensions`, and `catalogCoveredFeatures`, what the
run's whole Catalog covers) for the per-extension report, so the readers
target v3 and warn on older sidecars, prompting a regenerate. v4 added the
self-checks (ADR-0010): an `assertions` array (readers keep kinds they don't
know, so later kinds don't need a bump), `resultImages`, and
`usesGroundTruth`/`groundTruthEvaluated`/`groundTruthReason`; older sidecars
read as compared exactly when they have channel scores.
