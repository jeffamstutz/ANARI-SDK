# AGENTS.md

This file provides guidance to coding agents working in the CTS. See the parent
`AGENTS.md` for overall SDK context, and `CONTEXT.md` here for the vocabulary
(Test / Axis / Permutation / Variant / Case / Channel / Ground truth / Workdir).

## Overview

The CTS (Conformance Test Suite) validates ANARI device implementations. It is a
self-contained C++ command-line tool, `anariCts`, that renders each test, checks
its Cases against each other on the device's own output (effect for a
Permutation axis, equivalence for a Variant axis, ADR-0010) and each Case on
its own raw channel values (exact checks), scores them against
ground truth generated by a reference device (halcyon's `preview` renderer,
or helide when halcyon can't be loaded) where the Test has it,
*and* reports on the results tree (`report`, ADR-0008). A thin Python
layer (`ctsReport.py`) is retained only for the one output not worth porting to
C++ — the `reportlab` PDF. Everything communicates through files only — there is
no pybind11, no JSON scene format, and no Python orchestration (these were
removed; see `docs/adr/0001`–`0002`).

## Build Commands

```bash
# From the SDK root build directory. The tool builds under BUILD_CTS or BUILD_TESTING.
cmake -DBUILD_CTS=ON -DBUILD_HELIDE_DEVICE=ON ..
cmake --build . -j
```

Relevant targets: `anariCts` (the CTS tool), `anari_cts_core` (the internal
static library holding the catalog + runner), `anari_test_scenes` (shared scene
and generator utilities), and `anariCatalogTests` (the unit tests).

### Running locally

A stale install of the anari libs on `LD_LIBRARY_PATH` can shadow a fresh build
("undefined symbol" at runtime). Prepend the build dir when running:

```bash
cd build
LD_LIBRARY_PATH="$PWD:$LD_LIBRARY_PATH" ./anariCts run helide --workdir /tmp/run
LD_LIBRARY_PATH="$PWD:$LD_LIBRARY_PATH" ./anariCatalogTests
```

## Running the suite

```bash
anariCts generate --workdir myrun      # ground truth from the reference device (halcyon, else helide)
anariCts run helide --workdir myrun    # render + score a candidate against it
anariCts run rtx --workdir myrun -p ambientSample=4   # custom renderer params
anariCts report myrun [--all] [--html out.html] [--embed]  # text + optional HTML
python ../cts/ctsReport.py report myrun --pdf out.pdf      # PDF only

anariCts list [--filter <pat>]         # enumerate the catalog
anariCts query-features <device>       # device extensions
anariCts query-metadata [--filter <pat>]   # catalog metadata as JSON (no device)
anariCts query-device-info <device>    # device introspection: object subtypes + parameter metadata
anariCts check-properties <device>     # per test: runnable vs skipped + missing features
anariCts check-discrimination --workdir myrun [--all]  # Ground truth that can't tell its Cases apart
```

`check-discrimination` reads the Ground truth `generate` wrote (no device) and,
for every pair of Cases differing in one Permutation value (not Variant,
`frame_<channel>_type` or `.noEffectCheck` axes), scores one's Ground truth
against the other's with the Test's own thresholds. A pair that passes is
indistinguishable: the Ground-truth comparison can't tell those two values
apart. It exits 1 on any such pair not on the allow-list,
`tests/IndistinguishableGroundTruth.cpp` (each entry with its reason; `--all`
lists the allowed ones too), and 2 when there is no Ground truth to compare.
The ctest `cts_tool::discrimination::check` (with `BUILD_HELIDE_DEVICE`) runs
it on the default Reference device's Ground truth: halcyon when it is on the
loader path, else the helide fallback (as in the main CI, which builds helide
only). The allow-list holds for both.

`query-device-info` is genuine device introspection (the old `anariInfo`
capability): `--type`/`--subtype` restrict by name substring, `--skip-parameters`
lists subtypes only, `--info` adds per-parameter default/min/max/use/values/
element types/description/source extension. It is distinct from
`query-metadata`, which dumps the catalog's shape.

`--filter` is a substring or glob (`*`,`?`) matched case-insensitively over a
test's `<category>/<test>` id; a pattern with two `/` is also matched over a
Case's `<category>/<test>/<case>` id, to select some Cases of a Test; the partners their self-checks need are then
rendered as support renders (images only, not counted). `run` and `report`
exit non-zero on any failure.

`run` without ground truth still evaluates the self-checks: a Case that passes
them is "passed, Ground truth not evaluated" (counted on its own line), and
only a Case with nothing to evaluate is skipped. `generate` writes a Variant's
shared ground-truth file from its first value's Case, skips `.noGroundTruth()`
Tests, and warns when the reference device's own Variants disagree.

`run`, `generate` and `check-properties` gate Cases on the selected
renderer's own extensions when it reports any, else on the device's
(`RendererExtensions.h`, ADR-0005): `anariCts run halcyon` (renderer
`preview`) skips `camera/depth_of_field` as `renderer preview lacks a
required feature: ANARI_KHR_CAMERA_DEPTH_OF_FIELD` (matrix state `advertised,
renderer lacks it`), and `-r quality` runs it. helide's renderer reports the
device's list, so nothing changes there.

`generate` without `--device` uses halcyon's `preview` renderer (unless `-r`
names another; `--device halcyon` without `-r` uses `preview` too, see
`referenceRenderer()`), and helide's default renderer, with a notice, when
halcyon can't be loaded (ADR-0005). It records the device, renderer and
extensions in the Reference record, `ground_truth/reference.json` (failing,
exit 1, if it can't), and refuses (exit 2, nothing written) when that
record names a different library, device subtype or renderer (the record
also holds the renderer's own extensions, which its Cases gated on), unless
`--replace` clears `ground_truth/` first; the same device regenerating a slice
keeps the rest (`RunOptions::replaceGroundTruth`,
`RunSummary::referenceConflict`). `run` copies the identity into every Sidecar
(`reference`), and a Case missing Ground truth because the Reference lacked one
of its required extensions records them (`referenceMissingFeatures`) and is
skipped as `no ground truth: reference device (<name>) lacks <extension>`
rather than "run generate first". `report` shows the Reference next to the
device, and the matrix state `advertised, Reference device lacks it`.

Before the first Case, `run` and `generate` render a small probe frame (an
empty world). A device that can't render it (say, helide_gpu without SDL3 on
the loader path) stops the command with exit code 2 and one error naming the
device's own ERROR messages, instead of failing every Case. `run` then writes
`results/run.json` (not a Sidecar: it has no `verdict`), and `report` leads
with "device could not render: <reason>" and exits non-zero. A run whose device
renders the probe removes that record.

## Architecture

```
anariCts                 CLI dispatch: cts/src/main.cpp
  anari_cts_core          internal static CTS implementation
    DeviceIntrospection   frontend utility for query-device-info
    anari_test_scenes     shared scene and generator utilities
  Catalog                 in-C++ registry of every Test (one per-category file)
  Runner                  per Case: build world -> render each Channel -> exact checks
                          (ExactCheck) -> generate GT or score vs GT;
                          per Test: relational pass (Relations) -> sidecars
  Relations               pure effect/equivalence pass over a Test's Cases (ADR-0010)
  ExactCheck              per-Case checks over raw channel values; the evaluation seam
  Metrics                 SSIM / PSNR / changed fraction (single source of metrics, ADR-0004)
  Workdir / Sidecar       results/ ground_truth/ assets/ tree; per-Case sidecar JSON (ADR-0003)
  Report / HtmlReport     read the results tree -> text / HTML summary (ADR-0008)
ctsReport.py              reads the results tree too; retained only for the PDF
```

### Key source files (`src/anari_test_scenes/cts/`)

**Harness / runner:**
- `TestDef.h` — a registered Test: human-readable `description`, `build`
  (world), optional `cameraBuild` / `rendererConfig` hooks (ADR-0006) and
  `behaviorCheck` hook (with an optional `timeout` and `failOnDeviceErrors`,
  ADR-0009), axes, required features, thresholds (test-wide + per-channel),
  channels.
- `TestBuilder.{h,cpp}` — the `makeTest(...)` fluent builder. Note the verb is
  `requireFeatures()`, not the C++20 keyword `requires`. `covers(ext)` names a
  primary extension (the Test is evidence for it; also required);
  `requireFeatures()` alone declares support extensions. The shared support
  sets are in `cts/tests/Categories.h`.
  `requireFeatureFor(axis, value, ext)` gates one axis value: a device
  lacking `ext` skips exactly the Cases holding it (they take no part in
  effect or equivalence checks); use it for an extension only some Cases need.
  An effect pair (or Variant/derived expectation) whose partner was skipped
  that way is recorded as "not evaluated: partner `x` was skipped: ...", never
  dropped silently and never failed.
- `Axis.h` / `Case.{h,cpp}` / `Expansion.{h,cpp}` — axes expand into Cases
  (cartesian, or one-factor-at-a-time when `simplified`); variants share a
  ground-truth key, permutations get distinct ones.
- `Catalog.{h,cpp}` / `Filter.{h,cpp}` — the registry and its substring/glob filter.
- `BuildContext.{h,cpp}` / `Value.{h,cpp}` — per-Case axis values handed to
  `build()`, backed by `helium::ParameterizedObject`, plus the Case's frame size and
  camera projection (`newCamera()` builds a Test's camera and records its
  projection in one call).
- `Runner.{h,cpp}` — builds, renders, and scores Cases; owns renderer creation
  and baseline configuration, owns the default camera, and runs the behavior
  hook for behavioral tests: a timed one's Cases through its `CaseIsolation`,
  when it has one, and fails them on device errors if the Test asks.
- `Isolation.{h,cpp}` — `runProcess()` (start a process, kill it at a
  timeout; POSIX and Windows), `currentExecutable()`, and `CaseIsolation` /
  `ProcessCaseIsolation`: `anariCts run` re-running itself with
  `--isolated-case` for each Case of a timed Test (ADR-0009).
- `DeviceErrorLog.{h,cpp}` — the ERROR messages a device reported, recorded
  by the status callback, for `failOnDeviceErrors` and the probe frame.
- `DeviceProbe.{h,cpp}` — `probeDevice()`, the probe frame the Runner
  renders before the first Case.
- `DeviceFailure.{h,cpp}` — the run record (`results/run.json`) of a device
  that could not render the probe frame; files only, so `report` reads it.
- `FrameReadback.{h,cpp}` — validates mapped frame descriptors and converts
  supported per-Channel formats behind the shared map/unmap boundary; keeps
  the raw depth (`float`) and ID (`uint32_t`) values for exact checks.
- `ExactCheck.{h,cpp}` — exact checks (ADR-0010): the `ExactCheck` context
  (axis values, frame size, typed channel views, `project()`), its helpers
  (`allPixels`, `matches`, `backgroundOutside`, `measure`) and the findings
  they record, `evaluateExactChecks` (one Case, pure; the runner's per-Case
  call) and `evaluateSelfChecks` (the evaluation seam: a Test's exact checks
  and relations over supplied channel data, no device).
- `CameraProjection.{h,cpp}` — what a Case's camera does to a world point
  (perspective or orthographic, with its image region), for `project()`.
- `ConvergenceGuard.{h,cpp}` — the convergence guard (ADR-0010, "Convergence
  guard"): the accumulation stop condition (`accumulationDone`), why the guard
  can't run (`notGuardedReason`, recorded as the Sidecar's `notGuarded`), the
  decision on one Case (`judgeConvergence`) and guarding every Case a
  relational assertion reads, failing those that read an unconverged one
  (`guardRelations`); pure + unit-tested. The runner measures each Case in its
  own render, accumulating its color frame again once its image is read
  (`Runner::renderChannels`). Relational assertions need a converged
  Candidate: raise `--accumulation` until the `convergence` assertions pass
  (`cts/README.md` lists measured counts). A device that stops refining while
  still noisy is not caught (operator's responsibility).
- `FrameAccumulation.{h,cpp}` — the `KHR_FRAME_ACCUMULATION` behaviour check
  behind `frame/progressive_rendering`: convergence towards a many-render
  image, restart after a world change, and `refinementProgress` where reported.
  It drives an `AccumulationTarget`, so stub frames unit-test it. The Test
  runs through a pinhole and, where the renderer lists depth of field,
  through a lens whose aperture needs sampling (ADR-0010 67).
- `FrameFormats.{h,cpp}` — resolves a Case's per-Channel output `ANARIDataType`
  from its `frame_<channel>_type` axis (color/albedo/normal); pure + unit-tested.
- `RendererExtensions.{h,cpp}` — what a run gates Cases on (ADR-0005): the
  selected renderer's own extensions (`queryRendererExtensions`: object
  introspection, else the renderer's `extension` property) when it reports
  any, else the device's (`gatingExtensions`, pure), which of a Case's
  missing extensions only the renderer lacks (`rendererMissingFeatures`), the
  skip reason naming the renderer (`featureSkipReason`), and the subtype
  `default` creates (`resolveRendererSubtype`). `anariCts` fills
  `RunOptions::device.rendererExtensions`; the Runner gates and records.
- `RendererParams.{h,cpp}` — pure parsing of CLI `--renderer-param NAME=VALUE`
  overrides into ANARI-typed bytes (unit-tested). The runner resolves each
  name's type from device introspection (falling back to inference) and sets it
  on every Case's renderer before the Test's own `rendererConfig`, so it stays
  device-agnostic and a renderer Test still wins on conflict. A Test can also
  ask for renderer parameters itself (`.rendererParam(name, value)`, the same
  text form): the runner sets them, after its baseline and before the CLI's
  overrides, only when the selected renderer subtype lists them
  (`supportedRendererParams`; `default` is the device's first subtype when it
  isn't listed), and records what it set in the Sidecar (`rendererParams`,
  additive in v4). The light Tests use it for `ignoreAmbientLighting=false`
  and the ID-channel Tests for `resolutionDivider=1`, so a mode a renderer
  has by default doesn't fail it on a Test's assumption.
- `FrameSize.{h,cpp}` — a Case's frame size from its Test's `.frameSize`
  hook (`resolveFrameSize`, pure), or the skip when it isn't whole pixels.
- `Metrics.{h,cpp}` / `Image.{h,cpp}` — SSIM/PSNR, `changedFraction` (and its
  mask, optionally under a selection mask) for the self-checks, the
  derived-expectation helpers (`crop`, `hconcat`, `vconcat`, `maskedBy`,
  `regionComposite`),
  `meanAbsoluteDifference` for the accumulation check, and PNG I/O (stb).
- `Discrimination.{h,cpp}` — `check-discrimination`: the pairs of Cases that
  differ in one Permutation value (`discriminationPairs`, pure), scoring their
  Ground truth against each other with the Test's thresholds, and matching the
  indistinguishable ones against the allow-list. The allow-list itself is
  `tests/IndistinguishableGroundTruth.cpp`.
- `Reference.{h,cpp}` — the default Reference device and its helide fallback
  (ADR-0005), and the Reference record `generate` writes of the one it used
  (`ground_truth/reference.json`: library, device, renderer, extensions),
  with `referenceConflict()`, the reason `generate` refuses to mix devices in
  one workdir, and `clearGroundTruth()` for `--replace`; `run` reads the
  record to say a Case lacks Ground truth because the Reference lacked one of
  its extensions.
- `Relations.{h,cpp}` — the pure relational pass (ADR-0010): groups of Cases
  differing in one axis, effect (all pairs, attributed to the later Case) and
  equivalence (a derived expectation over the Case's siblings; a Variant's is
  the first value's Case), the default tolerances
  (`SelfCheckDefaults`), which partners a filtered run must render
  (`renderSet`), the verdict as a conjunction (`settleVerdict`), and reading a
  Case's images back from the results tree (`loadCaseRender`). No device.
- `Workdir.{h,cpp}` / `Sidecar.{h,cpp}` — the results tree layout and the
  versioned per-Case sidecar contract (carries the producing `device` identity
  since schema v2 plus optional Test descriptions; `Workdir` also keys the
  per-channel diff/threshold images). `Sidecar` both writes (`toJson`/
  `writeSidecar`) and reads (`fromJson`/`readSidecar`) the contract.
- `Report.{h,cpp}` — reads the results tree (`loadResults`), aggregates it
  (`summarize`, `runDevice`, and per extension `extensionCoverage` over the
  canonical KHR list from `code_gen/api/` and the covered extensions the run
  recorded of its Catalog, `runCoveredExtensions`, plus a `core` row), and
  emits the text summary. `kReportMetrics` is
  the single list of reported metrics. Pure; unit-tested.
- `HtmlReport.{h,cpp}` — renders the self-contained interactive HTML report
  (inline CSS/JS, optional base64 `--embed`); pure `htmlEscape`/`base64Encode`
  are unit-tested.
- `ScreenQuad.{h,cpp}` — a quad filling the frame of its own camera, with
  vertex attributes given as functions of screen position, so a Test knows
  which screen region holds which value (a sampler's border, an opacity
  cutoff) and derives what each region must show with `regionComposite`.
- `GeometryLayout.{h,cpp}` — pure deterministic Layout generation using typed
  shape and primitive-mode enums.
- `GeometryBuilder.{h,cpp}` — geometry-family specifications and ANARI
  publication; one entry point per supported family.
- `ParameterBinding.{h,cpp}` — checked constant/attribute/sampler/unset
  material bindings. `SurfaceBuilder`, `LightBuilder`, `SamplerBuilder`,
  `VolumeBuilder`, `InstanceBuilder`, `ViewBuilder`, and `WorldBuilder` own the
  remaining focused construction responsibilities.

`query-device-info` is a thin CLI adapter over the shared frontend utility in
`src/anari/DeviceIntrospection.cpp`; the same utility backs `anariInfo`.

**Tests (the catalog):** `cts/tests/<category>.cpp` (geometry, material, sampler,
light, camera, frame, renderer, instance, volume, synchronization) each define a
`register<Category>Tests(Catalog&)`. `BuiltinTests.cpp` wires them all into the
catalog. `tests/attributes.cpp` holds the parameter-depth Tests that cut across
categories: geometry attribute slots, uniform attributes, precedence,
face-varying normals, index and colour element types, surface `visible`, and
the image sampler element types (its Tests are registered in their own
categories). Its helpers are headers beside it: `AttributeColors.h` (the
colours each attribute holds), `RawArray.h` (arrays of fixed-point, sRGB and
64-bit element types, filled from bytes) and `SubjectShown.h` (the exact check
that keeps an equivalence from passing on empty frames). A Test whose Cases a
device may take the process down with (a device that throws on a valid
parameter) is a timed behaviour Test so each Case runs in its own process; the
`*_index_types` Tests do it by rendering both forms themselves.

`tests/motion.cpp` holds the motion blur family (camera shutter and rolling
shutter, camera motion, instance motion, triangle and quad motion
deformation; ADR-0010 46-50), registered in the camera, instance and
geometry categories; `tests/MotionScene.h` is its scene (rest camera,
subject extents and paths, the rolling shutter's duration), shared with its
unit tests.

`tests/optics.cpp` holds the camera's optics, depth of field and stereo
(ADR-0010 51-54), registered in the camera category: a near and a far plate,
judged by edge width (depth of field) and by the near plate's offset from the
far one, an eye's disparity (stereo), so no check depends on the lens or
convergence model the spec leaves open; `tests/OpticsScene.h` is its scene,
shared with its unit tests.

`tests/fields.cpp` holds the spatial field Tests (ADR-0010 55-60),
registered in the volume category, plus `geometry/isosurface_sphere`: one
linear ramp sampled into structuredRegular, unstructured hexahedra,
tetrahedra and pyramids (no wedges, ADR-0010 58) and nanovdb renders the same volume (two views each), the filters differ on a
coarse grid and cubic reproduces a ramp away from the boundary, data element
types match FLOAT32, and a step transfer function makes a field's extent
exact. `tests/fields.h` and `tests/VolumeScene.h` (the volume framing, shared
with `volume.cpp`) hold its fields and view for the unit tests.
`tests/NanoVdbGrid.{h,cpp}` builds a NanoVDB grid in code with the headers
vendored in `external/nanovdb` (Apache-2.0, NanoVDB 32.9.0), so no grid file is
checked in.

Two header-only helpers sit beside them: `tests/ScreenScene.h` (triangles laid
out in the screen camera's coordinates, and which pixels they cover) and
`tests/ParameterQuery.h` (`listsParameter`, for a query-level check that a
device's introspection lists a parameter; the denoise and MPI Tests use it, as
`anariCts` does not run MPI ranks and no SDK device has a noisy setup to
calibrate a denoise bound on).

The light primary-visibility Tests do not assume what a hidden light leaves
behind: the `visible` axis has a value `absent` that renders the scene without
the light, and `visible=false` is a derived expectation (that render inside
the light's footprint, the default render elsewhere).

**Unit tests:** `tests/unit/test_cts_*.cpp` (catalog/expansion/filter/builder,
metrics, relations, discrimination, frame accumulation, results/sidecar/workdir,
report/html, runner, isolation, renderer extensions (its halcyon case is
hidden, `anariCatalogTests "[halcyon]"` with halcyon on the loader path);
`motion` judges the motion and shutter Tests
on synthetic images, as `optics` does the depth-of-field and stereo Tests;
`volumes` reads a built NanoVDB grid back and judges the spatial field
Tests on synthetic images;
`anari12` and `small_extensions` judge the
ANARI 1.2 Tests and the small extensions' Tests (array region, transform
arrays, light primary visibility, denoise) on synthetic images).
`test_cts_parameter_coverage.cpp` (tag `[parameter_coverage]`) runs every Case's
build, camera and renderer hooks against a recording device and requires every
parameter that the spec JSON (`code_gen/api/khr_*.json`) defines for an
extension the Catalog covers to be set by some Test, or to be on its allow-list
with a reason (a stale entry fails too); `name` is exempt, and a parameter of
an object type without subtypes, or one the spec JSON gives every subtype
under the subtype `default` (the camera extensions'), counts when set on any
object of the type. Add
a Test, or an allow-list entry saying what stops one, whenever the extension
gains a parameter. Behaviour checks are not run there, so a parameter only
a behaviour check sets is allow-listed.
Pure tests are tagged `[cts]`; device-backed ones add `[helide]` and self-skip if
no device loads. Images for pure tests are generated in code
(`tests/unit/cts_test_images.h`: solid, gradient, rectangle, disc); never add
an image file.

**Sink smoke test** (`test_cts_sink_smoke.cpp`, tag `[sink_smoke]`, ctest
`unit_test::cts::sink_smoke`): runs every Case's `build`, `cameraBuild` and
`rendererConfig` hooks against the `sink` device with feature gating bypassed, so
a Test no SDK device can run still has its build code executed. It requires that
nothing throws, `build` returns a non-null world and `cameraBuild` a non-null
camera. `sink` answers no property, so the world bounds are the fixed
`[-1, 1]` box. A `behaviorCheck` is not run. It catches crashes, exceptions and
null objects; it cannot catch a wrong parameter name or value, because `sink`
accepts any call. Self-skips when `sink` isn't built (`BUILD_SINK_DEVICE`).

**Python:** `ctsReport.py` — the `report --pdf` path only; it reads the results
tree exactly as the C++ `report` does. Text and HTML live in C++.

## Extending the CTS

**New Test:** add a `makeTest(...)....registerInto(catalog)` to the relevant
`cts/tests/<category>.cpp`. Author the world in `build()` with ANARI C++ calls
plus the focused `*Builder.h` helpers; add a short `description()` of the
primary check, then declare axes, the primary extension(s) with `covers()`,
the support extensions the scene can't do without with `requireFeatures()`
(a missing one must skip the Test, not fail it; the shared sets in
`cts/tests/Categories.h` include the default perspective camera, so a Test
that brings its own camera requires that one instead), and channels.

Every Permutation axis is an effect check and every Variant axis an
equivalence check (ADR-0010). When a value must look like something derived
from its siblings (a crop, a concatenation, the same outside a mask), declare
it with `.expectDerived(axis, value, description, fn)` using the helpers in
`Image.h` (`crop`, `regionPixels`, `hconcat`, `vconcat`, `maskedBy`,
`regionComposite`); a Case
that needs another frame size than the run's gets `.frameSize(...)`
(`regionFrameSize` for a normalized region). Pick values whose effect shows in a good share of
the frame (the default minimum is 1 % of pixels changed by more than 8 levels);
rework the scene rather than loosen it (`.effectMargin`) when a change is too
subtle. An `.effectMargin` or `.equivalenceTolerance` override needs its
measurements on two devices written beside it (ADR-0010 65 for margins, its
"Volume equivalence" section (ticket 08) for tolerances; the PBR lobe margin,
ADR-0010 66, is the example). On a PBR lobe Test, a framing that enlarges the
lobe also lowers the Ground-truth PSNR of a device that shades it, since the
Reference device doesn't (ADR-0010 68): measure both. Opt an axis out (`.noEffectCheck(axis, reason)`, or `.noEffectCheckOn(axis,
library, renderers, reason)` for a device known not to render the parameter) only when its
effect can't be judged by image difference.

When the answer is analytic (an ID at a pixel, a depth, "background outside
this region"), add an exact check: `.expectExact(label, fn)`, where `fn`
takes an `ExactCheck &x` and reports through its helpers, e.g.
`x.matches(name, x.ids(Channel::PrimitiveId), expectedFn, 0, &where)`,
`x.backgroundOutside(name, x.depth(), subject, "beyond the farthest subject",
beyondFar)` or `x.measure(name, value, Limit::AtLeast, bound)`. The 1.2 draft
gives no value for a pixel without a hit, in any ID channel or in depth, so a
background check requires only what the spec implies: an ID background holds
no subject's ID, and a depth background is no closer than the farthest
subject. Don't require `~0u`, `+inf` or any other specific value. Use `x.project(p)` to find
where a world point lands; the runner's camera records its projection, and a
Test with its own `.camera` hook builds its camera with
`ctx.newCamera(projection)` (it creates the camera the `CameraProjection`
describes, aspect from the Case's frame, records it, and leaves it
uncommitted for the Test's own parameters) for `project()` to work. Don't use
`.behavior` for a property of one rendered image. Unit-test a check with the
evaluation seam (`evaluateSelfChecks`, `ExactCheck.h`): build a correct and a
wrong channel in code with `idChannel`/`depthChannel`
(`tests/unit/cts_test_images.h`) and show the check passes the first and
fails the second (`tests/unit/test_cts_exact.cpp` does this for
`frame_primitiveID_channel`). For a Test no SDK device can run, that
synthetic positive and negative is the validation; say so in the ticket's
answer.

Declare `.groundTruth(reason)` when
appearance has no analytic answer; a Test that declares neither it nor
`.noGroundTruth()` is self-checked only (as `.noGroundTruth()` says explicitly,
which is the clearer form for a Test whose checks are complete), and one with
nothing to evaluate is skipped. A Test with Ground truth must also pass
`check-discrimination`: its Permutation values' Ground truth must fail as each
other's. An allow-list entry needs a specific reason (what the Reference
device can't show, or how little of the frame the change touches), never a
bare "indistinguishable".

An axis whose unset value is the spec's default for another value (a `filter`
or `wrapMode` left unset, `side` unset, `layout` unset) is not a second
Permutation value: declare the unset value with `.expectDerived` from the
explicit default (so the pair is judged for equality, not effect), or make the
axis a Variant. A frame buffer type axis (`frame_color_type`, ...) is a
Permutation whose float and sRGB values are derived expectations of the linear
one (`tests/FrameTypeAxis.h`): the sRGB buffer's bytes are the encoded colours,
and the 8-bit comparison image is the buffer, undecoded.

**New synchronization rule** (or any check a device fails by hanging): a
behaviour Test in `cts/tests/synchronization.cpp` with `.timeout(...)` and
`.failOnDeviceErrors()`. Make only calls the spec allows, force the state the
rule is about deterministically (e.g. map a shared array to hold a render
off) rather than by timing, and pick the next rule from ADR-0009's list.

**New per-Case axis the runner must act on** (e.g. a new output format): resolve
it in `FrameFormats.cpp` (pure, unit-test it) and honor it in `Runner.cpp`.

**New metric:** add it to `Metrics.{h,cpp}`, record it in the runner's
`ChannelResult`, add it to `kReportMetrics` in `Report.h` (the C++ text/HTML),
and to the `METRICS` list in `ctsReport.py` (the PDF). There is exactly one
metric *implementation*, in C++; the two reported-metric lists are just display
order for two independent readers of the one contract.

**Sidecar schema change:** the sidecar is a versioned cross-language contract
(ADR-0003) with two readers — the C++ `Sidecar` reader (`fromJson`) behind
`report`, and `ctsReport.py` for the PDF. An additive field, read with a
default on both sides, need not bump `kSidecarSchemaVersion` when a reader that defaults it cannot misread an older
Sidecar: no older Sidecar can hold the thing the field describes, or the
default is what an older Sidecar meant. Bump it when a change is breaking, *or*
when consumers must tell an older Sidecar apart to read it right (a new field
whose absence would be misread), and update both readers in lockstep.
v2 did the latter: it added the `device` object that labels a run (plus the
optional per-channel `diffImage`/`thresholdImage` debug paths). v3 added the
extensions behind a Case (`requiredFeatures`, `coveredFeatures`,
`missingFeatures`, `device.extensions`, and `catalogCoveredFeatures`, what the
run's whole Catalog covers) for the per-extension report, so the readers
target v3 and warn on older sidecars, prompting a regenerate. v4 added the
self-checks (ADR-0010): an `assertions` array (readers keep kinds they don't
know, so later kinds don't need a bump), `resultImages`, and
`usesGroundTruth`/`groundTruthEvaluated`/`groundTruthReason`; older sidecars
read as compared exactly when they have channel scores. Within v4, derived
expectations added `frameSize` (absent means the run's size, the only size
before them) and per assertion `expectation`/`expectedImage`/`expectedMaskImage`,
and exact checks added `exact` assertions (`label`, `pixels` or
`measurement`); no older Sidecar can hold either, so neither needed a bump.
The Reference device added `reference` (whose Ground truth the run read) and
`referenceMissingFeatures` (ADR-0005); an older Sidecar reads as "Reference
unknown", which is what it was. Renderer-level gating added
`device.rendererExtensions` (what the run's renderer reported) and
`rendererMissingFeatures` (the missing extensions the device advertised but
the renderer lacked); an older Sidecar gated on the device alone, which is
what their absence means. The convergence guard added `notGuarded` (why it
didn't run for the Case's relational assertions, empty when it ran); it is
written by every run and absent from an older Sidecar, which the readers
keep as "unrecorded" rather than "guarded", so it needed no bump.
